# 项目规划

版本：0.1 · 日期：2026-10-22 · 状态：工作基线，待原型验证。

## 1. 产品定位

玩家在空间、资金和电力有限的条件下建立工厂，通过诊断与调度稳定完成订单。

目标体验是优化、自动化和逐步扩张，不以大量建筑或超大地图作为首发卖点。视觉方向为原创工业像素美术，优先保证机器、物品、方向和故障状态清晰可读。

差异化假设：可解释的生产诊断，加上有限资源下的调度与风险决策，能让小规模生产线产生多种值得比较的改造方案。此假设必须通过原型和外部试玩验证，不能仅凭题材判断商业价值。

“黑箱”是暂定主题，不意味着隐藏必要规则。玩家应能理解堵在哪里、为什么停机、改造带来了什么变化。

## 2. 核心循环

1. 接受订单，查看原料和产能需求。
2. 建造或调整生产线，开始自动加工与交付。
3. 从缓存、停机原因和吞吐量发现瓶颈。
4. 在扩产、改线、缓存、供电与维修之间做取舍。
5. 获得收入，解锁更复杂的合同和生产链。

首个闭环仅包含铁矿石、铁板、零件，以及原料仓、传送带、冶炼机、冲压机、仓储和交付站。分流作为物流配套能力按原型需要引入，不做多等级运输体系。

目标为一局约 15～20 分钟的纵向切片，包含建造和思考时间。这是体验目标，尚未实测。

## 3. 开发边界

| 阶段 | 包含 | 暂不包含 |
| --- | --- | --- |
| M1 核心原型 | 网格、旋转拆除、物流、两条配方、仓储、基础状态诊断、测试夹具 | 美术定稿、科技树、随机地图 |
| M2 优化闭环 | 订单、资金、全厂电力预算、供电优先级、吞吐量诊断 | 电线网络、复杂电网 |
| M3 纵向切片 | 可预测磨损、停机维修、版本化存档、引导、基础音画、完整一局 | 扩充大量配方 |
| M4 商业评估 | 外部试玩、竞品与命名调研、内容成本和发行评估 | 未验证即确定完整上市范围 |

首发候选形式是渐进解锁的合同关卡。是否加入自由沙盒，等核心体验验证后决定。

默认不做：联机、流体、铁路、地下物流、战斗、开放世界、模组支持、多平台同步首发。需要改变边界时，先记录收益、代价和替换掉的工作。

## 4. 系统原则

- 物流：离散物品、有限缓冲、明确连接方向；堵塞可逆，物品不可凭空增减。
- 机器：数据驱动配方；开始加工时扣料，完成后输出，输出满时不得丢弃产品。
- 电力：先用全厂共享功率预算与优先级，不做电线网络；缺电必须解释清楚。
- 订单：交付目标明确，初期不设置导致经济死局的强制罚款。
- 故障：从可预测磨损降效开始；如果维修只增加重复点击而不改变决策，应简化或移除。
- 诊断：至少区分缺料、输出堵塞、缺电、维修和正常加工；同时展示近期吞吐量与缓存。
- 资源：优先限制资金、场地和电力；原型不加入矿脉枯竭。
- 存档：显式版本号、稳定内容 ID、临时文件替换和备份恢复；不直接序列化整个场景树作为长期格式。

## 5. 技术方向

Godot 4.x 稳定版，GDScript。M1 已核验并锁定 Godot 4.7.2 标准版及本地开发环境；尚未安装或验证发行导出模板，不把“最新版本”当作兼容性保证。

| 职责边界 | 负责内容 |
| --- | --- |
| simulation | 固定步长的物流、配方、电力、订单计算；不依赖渲染帧率 |
| world | 整数网格、建筑占位、端口连接、建造合法性 |
| content | 用 Godot Resource 定义建筑与配方，稳定 ID 引用 |
| presentation | 场景、输入、像素美术、音效、诊断 UI；呈现模拟结果 |
| persistence | 版本化状态、迁移、写入失败处理与恢复 |

这些是职责边界，不要求提前建立空目录或框架。网格、物流、存档由项目实现并测试；UI、输入和场景优先使用引擎能力或许可清晰的组件。

模拟采用明确更新阶段，避免节点遍历顺序影响产量。物品状态不依赖每物品一个独立运行节点。先用单线程简单实现，性能测量后再决定是否需要额外优化。

| 里程碑 | 交付物 | 退出标准 |

| M2 优化闭环 | 可玩的订单与电力流程、诊断面板 | 测试者能定位瓶颈，改造收益能用吞吐量衡量；记录误判点 |

## 7. 验证重点

- 资源守恒按配方转换计算，不能简单比较加工前后的物品个数。
- 覆盖满仓、断路、争用、旋转、拆除时在制品处理及阻塞解除。
- 验证确定性：相同初始状态与命令序列产生相同结果，渲染帧率不影响模拟。
- 验证存档迁移、损坏存档、写入失败，以及中途加载与连续运行等价。
- 性能使用固定布局，记录建筑数、物品数、硬件与逻辑步耗时；规模上限待测量。
- 试玩先观察玩家能否解释问题，再观察是否愿意再次优化；不要用内容量掩盖诊断困难。

## 8. 商业与许可

商业模式暂定 Steam 单机买断，后续扩展由实际需求决定。名称与竞品检索尚未执行，Steam 同名查询不能替代目标市场的商标检索。

Godot 使用 MIT 许可；发行时核验并提供适用的引擎版权、许可及所用组件声明。资产、字体、音效和依赖从引入时记录来源、许可及商业使用条件。不复制现成游戏美术或架构，不添加不必要的第三方依赖。
